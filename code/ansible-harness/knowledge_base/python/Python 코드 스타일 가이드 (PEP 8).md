# Python / 파이썬 코드 스타일 가이드 (PEP 8) 통합 문서

이 문서는 Python / 파이썬 프로그래밍 언어의 공식 스타일 가이드인 **PEP 8** 규칙을 상세히 설명합니다. 주로 파이썬 개발자가 코드의 가독성, 일관성, 유지보수성을 높이기 위해 참고하며, 핵심 키워드는 **PEP 8, 파이썬 스타일 가이드, 코드 컨벤션, 들여쓰기, 작명 규칙**입니다.

## 1. 개요 및 철학 (Introduction & Philosophy)

* **가독성 우선:** "가독성은 중요하다(Readability counts)"는 파이썬의 핵심 철학입니다. 코드는 작성되는 것보다 읽히는 경우가 훨씬 많으므로 가독성을 높이는 것이 스타일 가이드의 최우선 목표입니다.
* **일관성:** 이 가이드를 따르는 것도 중요하지만, 프로젝트나 모듈 내의 일관성을 유지하는 것이 더 중요합니다.
* **예외 상황:** 가이드 적용 시 가독성이 떨어지거나, 하위 호환성을 깨뜨리는 경우, 또는 스타일 가이드 도입 전 작성된 코드를 수정할 이유가 없는 경우에는 규칙을 무시할 수 있습니다.

## 2. 코드 레이아웃 (Code Layout)

### 2.1 들여쓰기 (Indentation)

* **4칸 공백:** 각 들여쓰기 단계마다 반드시 **4칸의 공백**을 사용합니다.
* **탭(Tab) 사용 금지:** 파이썬 3에서는 탭과 스페이스의 혼용을 허용하지 않으며, 오직 **스페이스**만을 사용해야 합니다.
* **연속 줄 처리:** 괄호 안의 암시적 줄 결합을 사용하여 요소를 정렬하거나, **내어쓰기(Hanging indent)**를 사용합니다.


아래는 권장되는 들여쓰기 방식의 예시 코드입니다.

```python
# 추천: 여는 구분 기호에 맞춘 수직 정렬
foo = long_function_name(var_one, var_two,
                         var_three, var_four)

# 추천: 내어쓰기 (첫 번째 줄에 인자 없음, 추가 들여쓰기로 본문과 구분)
def long_function_name(
        var_one, var_two, var_three,
        var_four):
    print(var_one)
```

### 2.2 줄 길이 및 줄 바꿈

* **최대 줄 길이:** 코드는 한 줄당 최대 **79자**, 독스트링 및 주석은 **72자**로 제한합니다.
* **이항 연산자 위치:** 수학적 전통에 따라 연산자 **전**에서 줄을 바꾸는 것이 가독성에 좋습니다.

아래 예시는 연산자와 피연산자의 매칭을 명확하게 보여주는 권장 패턴입니다.

```python
# 추천: 연산자가 피연산자와 매칭되어 가독성이 좋음
total = (first_variable
         + second_variable
         - third_variable)
```

### 2.3 공백 줄 (Blank Lines)

* 최상위 함수 및 클래스 정의 앞뒤로 **2줄**의 공백을 둡니다.
* 클래스 내 메서드 정의 앞뒤로는 **1줄**의 공백을 둡니다.

### 2.4 가져오기 (Imports)

* **별도의 줄:** 각 import는 별도의 줄에 작성합니다.
* **순서:** 파일 최상단에서 **표준 라이브러리 > 서드 파티 > 로컬 라이브러리** 순으로 그룹화하고 각 그룹은 빈 줄로 구분합니다.
* **절대 경로 권장:** `import mypkg.sibling`과 같은 절대 경로 사용을 권장합니다.
* **와일드카드 금지:** `from <module> import *`는 네임스페이스를 혼란스럽게 하므로 피해야 합니다.

## 3. 공백 규칙 (Whitespace)

### 3.1 불필요한 공백 피하기 (Pet Peeves)

괄호 안쪽 바로 옆이나 콤마, 세미콜론, 콜론 바로 앞에는 공백을 두지 않는 것이 원칙입니다.

```python
# 추천
spam(ham, {eggs: 2})

# 비추천
spam( ham[ 1 ], { eggs: 2 } )
```

함수 호출이나 인덱싱 시작 괄호 바로 앞에도 공백을 두지 않습니다.

### 3.2 연산자 주변 공백

* 할당(`=`), 비교(`==`), 불린(`and`, `or`) 연산자 주위에는 **한 칸의 공백**을 둡니다.
* 단, 함수의 **기본값 인수** 설정 시에는 `=` 주위에 공백을 두지 않습니다.

```python
def complex(real, imag=0.0):  # 추천: 기본값 인수 '=' 주변 공백 없음
    return magic(r=real, i=imag)
```

## 4. 작명 컨벤션 (Naming Conventions)

대상에 따라 권장되는 작명 스타일을 아래 표와 같이 구분합니다.


| 대상 | 스타일 | 예시 |
| :--- | :--- | :--- |
| **함수/변수** | `snake_case` (소문자와 밑줄) | `my_function`, `var_name` |
| **클래스** | `CapWords` (CamelCase) | `MyClass`, `Model` |
| **상수** | `UPPER_CASE` (대문자와 밑줄) | `MAX_OVERFLOW`, `TOTAL` |
| **패키지/모듈** | 짧은 소문자 (모듈엔 밑줄 가능) | `mypackage`, `module_name.py` |

* **피해야 할 이름:** 숫자 1, 0과 혼동될 수 있는 `l`(엘), `O`(오), `I`(아이)와 같은 단독 변수명은 사용하지 않습니다.
* **내부용 변수:** 내부 사용을 나타낼 때는 이름 앞에 밑줄을 붙여 `_single_leading_underscore` 형식을 사용합니다.

## 5. 주석 및 독스트링 (Comments & Docstrings)

* **주석 최신화:** 코드가 변경되면 주석도 반드시 업데이트하여 코드와 주석의 일치성을 유지해야 합니다.
* **블록 주석:** 관련 코드와 동일한 레벨로 들여쓰고, 각 줄은 `# `로 시작합니다.
* **인라인 주석:** 코드와 최소 **2칸 이상의 공백**을 두고 작성합니다.
* **독스트링:** 모든 퍼블릭 모듈, 클래스, 함수에 작성합니다. 여러 줄일 경우 닫는 따옴표(`"""`)만 별도의 줄에 둡니다.

## 6. 프로그래밍 권장사항 (Programming Recommendations)

* **싱글톤 비교:** `None`과의 비교는 항상 `is` 또는 `is not`을 사용하며, `==`는 쓰지 않습니다.
* **불린 확인:** 시퀀스(리스트 등)가 비어 있는지 확인할 때는 명시적으로 길이를 재기보다 시퀀스 자체의 참/거짓 성질을 이용하는 것이 파이썬다운 방식입니다.

```python
# 추천: 시퀀스의 빈 상태 확인
if not my_list:
    print("비어 있음")
```

* **람다 대신 def:** 식별자에 람다를 바인딩하는 대신 명시적인 `def`를 사용하여 함수를 정의합니다.
* **문자열 확인:** 접두사나 접미사를 확인할 때는 슬라이싱 대신 `.startswith()`와 `.endswith()`를 사용하여 가독성을 높입니다.

## 7. 도구 및 보조 수단 (Tools)

* **린터 (Linters):** 코드 스타일 위반을 자동으로 찾아주는 도구입니다.
    * **Flake8, Pylint, Ruff, pycodestyle** 등이 대표적입니다.
* **자동 포맷터 (Autoformatters):** 코드를 PEP 8 규격에 맞춰 자동으로 수정해주는 도구입니다.
    * **Black, autopep8, YAPF, Ruff** 등이 사용됩니다.
    * 특히 **Black**은 기본 줄 길이를 88자로 설정하며 엄격한 포맷팅을 제공하는 것으로 유명합니다.
