# Ansible Playbook 계층 구조 및 구성 요소(Play, Role, Block, Task) 상세 가이드

이 문서는 **Ansible / 플레이북(Playbook)**의 논리적 계층 구조와 각 구성 요소인 **Play, Role, Block, Task**에서 사용하는 모든 키워드와 제어 옵션, 그리고 예외 처리 메커니즘을 상세히 설명합니다. 주로 복잡한 인프라 자동화 환경을 설계하는 엔지니어가 참고하며, 핵심 키워드는 **플레이북(Playbook), 계층 구조(Hierarchy), 키워드(Keywords), 역할(Roles), 블록(Blocks), 예외 처리(Error Handling)**입니다.

## 1. 개요 및 버전 변경 사항 (Ansible 12 / Core 2.19)

* **템플릿 엔진 변경**: `ansible-core 2.19` 및 `Ansible 12` 버전부터 중요한 템플릿 변경 사항이 적용되었습니다. 이전 버전에서 허용되던 일부 동작이 보안 및 성능 문제로 리포팅되므로, 업그레이드 전 철저한 호환성 검증이 권장됩니다.
* **키워드 상속 및 특징**: 상위 객체(예: Block, Play)에서 설정한 지시어(`when`, `become`, `vars` 등)는 내부 작업에 자동으로 상속되어 적용됩니다. 일부 키워드는 객체 자체가 아닌 내부 객체의 기본값을 설정하기도 합니다.

## 2. Playbook 논리적 계층 구조 (Hierarchy)



플레이북은 최상위 계층부터 실제 작업을 수행하는 모듈 단위까지 명확한 실행 순서와 트리 구조를 가집니다.

### 2.1 트리 구조 상세
* **PLAYBOOK (최상위)**: 하나 이상의 Play를 포함하는 YAML 파일입니다.
* **PLAY_PREFIX**: Play 전체에 영향을 주는 전역 설정 구역으로, `hosts`, `become`, `vars` 정의가 포함됩니다.
* **실행 순서**:
    1.  `PRE_TASKS`: Role 실행 전 선행되는 작업 목록입니다.
    2.  `ROLES`: 재사용 가능한 독립적 작업 단위입니다.
    3.  `TASKS`: 플레이북의 주 실행 작업 목록입니다.
    4.  `POST_TASKS`: 주요 작업 및 Role 실행 후 수행되는 후행 작업입니다.
* **PLAY_POSTFIX**: Play 실행 완료 후의 전역 설정을 마무리합니다.

## 3. Play 키워드 상세 (Play Keywords)

**Play**는 특정 호스트 그룹에 대해 수행할 작업의 최상위 정의 단위입니다.

| 분류 | 키워드 | 상세 설명 |
| :--- | :--- | :--- |
| **식별/대상** | `name` | Play의 식별자로 로그 및 문서화에 사용됩니다. |
| | `hosts` | 작업을 실행할 대상 호스트 또는 그룹 목록입니다. |
| | `order` | 호스트 실행 순서를 정의합니다. |
| **권한 상승** | `become` | 권한 상승(예: sudo) 사용 여부(Boolean)를 결정합니다. |
| | `become_method` | 권한 상승 방법(sudo, su 등)을 지정합니다. |
| | `become_user` | 권한 상승 후 전환할 사용자 계정입니다. |
| | `become_flags` | 권한 상승 시 사용할 추가 플래그를 설정합니다. |
| **변수/데이터** | `vars` | Play 수준의 변수 사전(Dictionary)을 정의합니다. |
| | `vars_files` | 외부 변수 파일 목록을 로드합니다. |
| | `vars_prompt` | 사용자로부터 인터랙티브하게 입력을 받는 변수를 정의합니다. |
| **Fact 수집** | `gather_facts` | 실행 전 호스트 정보를 자동으로 수집할지 여부입니다. |
| | `gather_subset` | 수집할 Fact의 범위를 제한하여 성능을 최적화합니다. |
| | `gather_timeout` | Fact 수집 시 허용되는 최대 시간(초)을 설정합니다. |
| | `fact_path` | 로컬 Fact를 저장하거나 불러올 경로를 지정합니다. |
| **제어/전략** | `strategy` | 실행 전략(`linear`, `free`)을 지정합니다. |
| | `serial` | 병렬 실행 시 한 번에 작업을 수행할 배치 크기를 정의합니다. |
| | `any_errors_fatal` | 한 호스트라도 에러 발생 시 전체 Play 중단 여부를 설정합니다. |
| | `connection` | 사용할 연결 플러그인(ssh, local 등)을 지정합니다. |

## 4. Role 구조 및 호출 키워드 상세 (Role Keywords)

**Role**은 관련 변수, 작업, 핸들러 및 기타 아티팩트들을 독립된 디렉토리 구조로 묶어 재사용 가능하게 만든 단위입니다.



### 4.1 표준 디렉토리 구조
각 디렉토리에는 최소한 하나의 `main.yml` 파일이 포함되어야 자동 로드됩니다.
* `tasks/`: 역할이 실행할 주 작업 목록 파일입니다.
* `handlers/`: 역할 내외부에서 `notify`에 의해 호출되는 핸들러 정의입니다.
* `defaults/`: 역할의 기본 변수로, 우선순위가 가장 낮습니다.
* `vars/`: 역할 내에서 사용하는 고정 변수로, 우선순위가 높습니다.
* `files/`: `copy`나 `script` 모듈에서 참조할 파일 저장소입니다.
* `templates/`: Jinja2 템플릿 파일 저장소입니다.
* `meta/`: 역할의 메타데이터(의존성, 인수 검증 등)를 정의합니다.

### 4.2 호출 및 제어 키워드
| 키워드 | 구분 | 설명 |
| :--- | :--- | :--- |
| `roles` | 플레이 레벨 | 플레이북 최상위에서 역할을 정적으로 로드하여 실행합니다. |
| `import_role` | 태스크 레벨 | 역할을 **정적(Static)**으로 로드하며, 파싱 시점에 포함됩니다. |
| `include_role` | 태스크 레벨 | 역할을 **동적(Dynamic)**으로 로드하며, 루프나 조건문 사용이 가능합니다. |
| `tasks_from` | 옵션 | `main.yml` 대신 실행할 특정 태스크 파일명을 지정합니다. |
| `vars_from` | 옵션 | 특정 변수 파일을 지정하여 로드합니다. |
| `public` | 옵션 | 역할의 변수를 플레이 전역으로 공개할지 여부를 결정합니다. |
| `allow_duplicates` | 옵션 | 동일 역할을 동일 플레이 내에서 중복 실행하도록 허용합니다. (meta 설정) |

## 5. Block 구조 및 예외 처리 키워드 상세 (Block Keywords)

**Block**은 Task들을 논리적으로 그룹화하고, 프로그래밍의 try-catch와 유사하게 오류 처리를 수행합니다.



### 5.1 구성 섹션 및 키워드
* **`block`**: 실행할 주요 작업 목록을 정의하는 필수 섹션입니다.
* **`rescue`**: `block` 내 작업이 **실패(failed)**했을 때만 실행되는 복구 작업입니다.
* **`always`**: 성공/실패 여부와 관계없이 항상 마지막에 실행되는 정리 작업입니다.
* **특수 변수 (Rescue 내부 전용)**:
    * `ansible_failed_task`: 실패를 유발하여 `rescue`를 트리거한 작업 객체 정보를 담습니다.
    * `ansible_failed_result`: 실패한 작업이 반환한 상세 에러 데이터 및 결과값을 포함합니다.
* **제어 지시어**: `when`, `become`, `notify`, `ignore_errors` 등을 사용하여 블록 전체의 동작을 제어하며, 이는 내부 작업에 상속됩니다.

## 6. Task 키워드 및 실행 제어 상세 (Task Keywords)

**Task**는 Ansible 실행의 최소 단위이며, 모듈 실행 전후로 다양한 제어 속성을 가집니다.

### 6.1 동작 및 결과 제어
* **동작 정의**: `action` (모듈 지정), `local_action` (로컬 실행), `args` (모듈 인자 사전 전달)를 사용합니다.
* **결과 등록**: `register` 키워드로 작업 결과 데이터를 변수에 저장하여 이후 작업에서 사용합니다.
* **상태 판단**: `changed_when` 및 `failed_when` 조건식을 통해 Ansible의 기본 성공/실패 판단 기준을 사용자 정의합니다.

### 6.2 루프(Loop) 및 재시도
* **루프 제어**: `loop` 리스트를 사용하여 반복 실행하며, `loop_control`로 변수 이름 변경 등을 상세 제어합니다.
* **재시도 메커니즘**: `until` 조건이 참이 될 때까지 `retries` 횟수만큼 `delay` 초 간격으로 작업을 반복 실행합니다.

### 6.3 비동기 실행 (Async)
* **`async`**: 비동기 실행 시 허용되는 최대 작업 시간(초)을 설정합니다.
* **`poll`**: 비동기 작업의 완료 상태를 확인하는 시간 간격입니다. `0`으로 설정하면 확인 없이 다음 작업을 진행합니다.

### 6.4 기타 제어 지시어
* **`notify`**: 작업 결과가 `changed` 상태일 때 호출할 핸들러 이름을 지정합니다.
* **`ignore_unreachable`**: 네트워크 단절 등으로 호스트에 접속할 수 없는 경우 에러를 무시하고 진행합니다.
* **`tags`**: 특정 작업에 태그를 부여하여 플레이북 실행 시 `--tags` 옵션으로 선택적 실행이 가능하게 합니다.
