# 금융권 리눅스 에이전트 통합 관리 자동화

## 📖 Background Story
금융권 인프라를 관리하다 보면 항상 부딪히는 문제가 있습니다. 바로 **'보안과 모니터링을 위해 설치된 수많은 에이전트(Agent)의 파편화'**입니다.

Avamar(백업), CTM(배치), LSV(보안), Polestar(모니터링) 등 서버 한 대당 4~5개의 에이전트가 돌아가고 있는데, 이 에이전트들이 꼬이거나 업데이트가 필요할 때마다 시스템 엔지니어들은 수백, 수천 대의 서버에 일일이 접속해서 프로세스를 내리고 올리는 단순 작업을 반복해야 했습니다. 
"단순 점검을 넘어서, 직접 조치(Action)까지 자동화할 수는 없을까?" 
이 고민에서 출발한 코드가 바로 이 **리눅스 에이전트 통합 관리 자동화**입니다.

## ⚙️ Architecture & Features

### 1. 에이전트 생애주기 완전 통제
- `agent-avamar`, `agent-ctm`, `agent-lsv`, `agent-polestar` 등 각 에이전트 특성에 맞는 관리 스크립트 모듈화
- 상태 점검(Status Check) -> 서비스 정지(Stop) -> 서비스 시작(Start) -> 검증(Verify)의 파이프라인 구축

### 2. 금융권 망분리/폐쇄망 환경 고려
- 인터넷이 불가능한 환경에서도 로컬 Repository나 사전에 정의된 Playbook/Vars를 통해 오프라인으로 배포 및 컨트롤이 가능하도록 설계

## 📂 Directory Structure

```text
금융권-리눅스-에이전트-관리/
├── agent-avamar/       # Avamar 백업 에이전트 관리 플레이북
├── agent-ctm/          # CTM 배치 스케줄러 에이전트 관리 플레이북
├── agent-lsv/          # LSV 보안 에이전트 관리 플레이북
└── agent-polestar/     # Polestar 모니터링 에이전트 관리 플레이북
```

## 🚀 How it Works
단순히 `service restart` 명령을 던지는 것이 아니라, 프로세스가 실제로 내려갔는지, 데몬이 정상적으로 PID를 뱉어내는지까지 이중 삼중으로 체크하도록 작성되어, 스크립트 실행 후 사람이 다시 들어가서 확인할 필요가 없습니다.
