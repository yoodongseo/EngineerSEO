# 발전소 멀티벤더 인프라 예방점검 파이프라인

## 📖 Background Story
대형 발전소나 공공기관 인프라는 오랜 시간에 걸쳐 구축되기 때문에, 제조사와 OS가 파편화되는 이른바 **'이기종(Multi-vendor) 지옥'**이 펼쳐집니다. 
`Linux, Windows`는 기본이고 `L3, L4, SDN_Switch` 같은 네트워크 장비에 `Veritas, Hitachi, IBM` 등 구형 유닉스 기반 스토리지 시스템, 거기에 `Axgate, Secui` 같은 국산 보안 장비까지 한 곳에 뒤섞여 있습니다.

이런 환경에서 예방점검을 하려면 엔지니어 수십 명이 각자의 매뉴얼을 들고 장비에 붙어 콘솔을 두드려야 했습니다.
"이 12종류가 넘는 이기종 장비들을 하나의 점검 파이프라인으로 묶어낼 수는 없을까?" 
이 야심 찬 목표에서 시작된 것이 바로 이 **멀티벤더 인프라 예방점검 자동화**입니다.

## ⚙️ Architecture & Features

### 1. 동적 벤더 판별 (Dynamic Vendor Routing)
- 단일 진입점(`pre_play.yml`)에서 인벤토리에 정의된 `vendor` 변수에 따라 동적으로 해당 벤더의 점검 스크립트를 라우팅합니다.
- `Linux, L3, L4, Veritas, Ibm, Hitachi, Nas, Sdn_switch, Windows, Sdn_controller, Axgate, Secui` 등 12개 이상의 벤더 로직 통합.

### 2. Python Filter 기반의 결과 규격화
- 각 장비가 뱉어내는 로그 형식은 천차만별입니다. 이를 해결하기 위해 Ansible 모듈에 의존하지 않고 각 벤더 특화 파이썬 필터(`secui.py`, `syslog.py`, `raw.py` 등)를 자체 제작했습니다.
- 비정형 텍스트 데이터를 정형화된 JSON(`merged_value`)으로 가공하여 뱉어냅니다.

### 3. 결과 규격화 기반의 파이프라인 완성
- 이기종 환경의 파편화된 점검 데이터를 하나의 공통 JSON 포맷(`merged_value`)으로 규격화했습니다.
- 이를 통해 사내 솔루션에 점검 결과를 일관되게 전달하고 처리할 수 있는 안정적인 데이터 파이프라인을 완성했습니다.

## 🚀 The Impact
이 코드를 통해 엔지니어들은 더 이상 각 장비별 점검 명령어를 외울 필요가 없어졌습니다. 단 한 번의 실행으로 12종의 장비를 훑고, 규격화된 결과를 바탕으로 대시보드나 리포트 생성(Excel)으로 이어지는 완벽한 기반을 다진 상징적인 코드입니다.
